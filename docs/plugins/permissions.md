# 权限

[插件 API](../plugins.md) / 权限

权限在 `manifest.json` 中声明，本地插件列表展示权限说明。启用时自动提供已声明的能力，不弹出授权确认。

| 权限 | 范围 |
| --- | --- |
| `editor.read`、`editor.write` | 读取编辑内容、事务修改 |
| `files.read`、`files.write` | 文本文件与目录操作，含读取文件列表当前的选择与筛选 |
| `attachments.read`、`attachments.write` | 附件字节读写 |
| `index.read` | 查询 SQLite 索引 |
| `clipboard.read`、`clipboard.write` | 剪贴板文本 |
| `network` | 网络代理；不限制域名，仅做协议安全校验 |
| `secrets` | 本插件的系统凭据，见 [secrets](secrets.md) |
| `background` | 后台重复任务 |

`required` 与 `optional` 中声明的权限均在启用时生效，不区分手动授权。文件和索引访问范围跟随当前文件夹及已打开页签所属目录。

```json
{
  "permissions": {
    "required": ["editor.read"],
    "optional": ["network"]
  }
}
```

`network` 权限是一个开关：声明后即可访问任意 `http`/`https` 地址，不限制域名或端口。宿主只做协议安全校验——仅允许 `http`/`https` 协议、URL 不得内嵌用户名密码、非本机地址必须使用 `https`（本机指 `localhost`、`127.0.0.1`、`::1` 及常见内网网段）。重定向会逐跳重新校验。

未声明的能力不可调用。停用插件会停止其任务并清理运行资源。

调用未声明的能力会由宿主直接拒绝。插件捕获这次拒绝也只能在没有该能力的情况下继续运行，并且拒绝记录发生在宿主侧，插件无法隐藏这次调用。插件设置的本地列表会标出该插件尝试使用、但清单未声明的权限，便于判断是清单遗漏还是插件版本过旧。

未声明的能力不会被临时授予，也不会因为运行时申请而补发。修复方式是开发者补充声明并发布新版本，用户更新插件；声明变更后重新启用会按新清单重建授权。

更新时若新版本扩大了声明（新增权限），宿主会先列出新增项并要求确认，取消则保留当前版本。只缩减声明不会打断更新。

`api.permissions.request()` 为兼容接口，直接返回 `true`，不弹窗，也不增加清单之外的权限；新插件无需调用。
